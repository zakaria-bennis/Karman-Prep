# Karman portals: the shared design system and gallery

A self-contained Vite + React 19 + Tailwind 3.4 package. Nothing in `src/` of
the app imports it, and it imports nothing from the app: the 12 account
themes, the skill taxonomy and the plan prices are copied in, each with a note
saying where it came from and that Phase 2 reads the app's file directly.

## Run it

From the repo root: `npm run portals` (installs once, opens the gallery). Or
from this folder:

- `npm install` (once, needs the network)
- `npm run dev` then open http://127.0.0.1:5174/
- `npm run typecheck`, `npm run contrast`, `npm run shots`

Fonts load from Google Fonts in `index.html` (Hanken Grotesk 400 to 800, IBM
Plex Sans 400 to 600, IBM Plex Serif 400). Phase 2 self-hosts the same files.

## The gallery

- `#/` is the start page. Its switches are portal (student, parent, tutor,
  school, daily10), screen, role, plan (free, platform, plus, cohort,
  private10, private20, school), state (long-time, first-day, empty, loading,
  error, locked), device (phone 440, 375, iPad, desktop), theme (the 12 account
  themes, or follow the mode), mode (device, light, dark), type (hanken, plex),
  background (sky, ruled, contour, grain) and glass (refract, frost).
- Every switch is a query in the hash, so a link opens the same view:
  `#/?portal=parent&plan=cohort&device=desktop&theme=rose&state=loading`.
- `#/screen/<portal>/<id>?...&bare=1` shows one screen alone, filling the
  viewport, which is what the screenshot script uses.
- `#/system` is the kitchen sink: every token, component and state, the four
  backgrounds, both glass recipes, all icons and marks.
- The mode follows the device setting, dark when it states none; a theme
  overrides it (rule 33). The light fallback is Warm ivory, not Clean paper,
  whose surface is pure white (rule 3).
- The fixed clock is Saturday 2026-10-31, 09:41, so screenshots are stable.

## Questions run on the real quiz engine

The student portal no longer draws its own question screen. Its Daily 10, Endless,
Time trials, Full-length, Practice and Diagnostic screens keep their entry rows and
their locked, loading and error states, and open the matching mode of the quiz modes
prototype (`prototypes/quiz-modes`, `node prototypes/quiz-modes/server.mjs`, port
5180) in the same light or dark mode (`src/portals/student/quizModes.ts`).

## Folder layout and who owns what

| Path | What | Owner |
| --- | --- | --- |
| `src/design-system/` | tokens, theme provider, backgrounds, glass, icons, marks, components, `README.md` | the design system agent (this pass) |
| `src/plans/` | the plan ladder as data, `PlanProvider`, `usePlan()` | design system; Phase 2 reads offer.ts |
| `src/mock/` | people, skills, dates, questions, welcomes, rewards, events, the state switch | design system; portal agents add their own rows beside these, never a real student |
| `src/gallery/` | the start page, hash router, stage, kitchen sink, `routes.ts` | design system |
| `src/portals/student/` | screens and `routes.ts` | the student portal agent |
| `src/portals/parent/` | screens and `routes.ts` | the parent portal agent |
| `src/portals/tutor/` | screens and `routes.ts` | the tutor portal agent |
| `src/portals/school/` | screens and `routes.ts` | the school portal agent |
| `src/portals/daily10/` | the Daily 10 flow and end screen, `routes.ts` | the Daily 10 agent |
| `scripts/` | `shots.mjs`, `contrast.mjs`, `click-check.mjs`, `glass-contrast.mjs`, `tokens.mjs` | design system |
| `shots/` | screenshots, gitignored, regenerated by `npm run shots` | nobody |

A portal agent registers a screen by adding a `ScreenRoute` to its `routes.ts`
(`id`, `portal`, `title`, `roles`, `module` as a path under `src/portals/`,
for example `student/Home.tsx`, default export). The gallery and the
screenshot script pick it up. Keep every file under 300 lines, every screen
working at 375 wide with no sideways scroll, and read
`src/design-system/README.md` first.

## Checks

- `npm run typecheck`: `tsc --noEmit` on `src/`.
- `npm run contrast`: WCAG 2.1 ratios for every text token on every surface in
  all 12 themes and over each background's strongest mark; writes
  `contrast-report.md`; fails under 4.5:1 (3:1 at 24px and up).
- `npm run shots`: the start page, the kitchen sink and every registered
  screen at four sizes in light and dark, into `shots/`, with a sideways-scroll
  check (`--only`, `--themes`, `--devices` narrow it).
- `node scripts/click-check.mjs`: clicks every control on the kitchen sink and
  the start page and records what happened.
- `node scripts/glass-contrast.mjs`: samples the primary glass button's rendered
  pixels under its label in every theme and both recipes.
- The taste-skill app inspector:
  `node ../../.claude/skills/taste-skill/scripts/inspect.mjs --app http://127.0.0.1:5174/#/system --allow glass,shadow,heavy-shadow,gradient`
  (the allowances are rule 50's glass controls with their soft shadow, and the
  coin's fixed gold gradients from the approved end screen).
- Format from the repo root:
  `npx prettier --ignore-path /dev/null --write "prototypes/portals/{index.html,*.ts,src/**/*.{ts,tsx,css}}"`.

The repo's own gates (lint, format, tests, sizes, cf:build) skip
`prototypes/`, so run the checks above before a review.

## Sound

The approved end screen's sound rules, for the Daily 10 agent: soft sine tones
in one key (C major), one sound per real moment (about nine on the end
screen), no ticks, whooshes, typing or tap sounds, the payout as a coin
cascade synthesised in code (never a shipped sample), muted by default until
the student turns sound on, and still audible under reduced motion. The synth
lives in `prototypes/daily10-end/core.js` and is ported when that screen is.
