It hashes the supplied PDF, requires source question identity, validates the reviewed D assessment, and reaches the database only on a non-dry-run. This path does no OCR or provider rewriting.

It is intentionally absent from the public reviewed CLI. That pilot is evidence for private draft behavior, not permission to import the full corpus.
- Old admin PDF upload and dispatch return 410. This branch also makes `/api/cron/ingest-csv-inbox` return authenticated 410 and removes only its five-minute Worker schedule. Historical job GET, admin CSV upload, source-file viewing, payments, auth, email and other crons remain available. Admin CSV upload is not the A–G reviewed import route.

## Required gate before a production import is even proposed

Every item below must be evidenced against the **same frozen candidate release**. A boolean inside an editable question file is not independent approval.

1. **Frozen input identity:** pin exact SHA-256 bytes for the final reviewed JSON, original source PDF and page PNGs, final A/B/C/CF/D/E/F/G artifacts, and each included figure. Verify their current-version and cross-artifact bindings. Preserve source wording, math tokens, passages, underlines and figure information; no extraction or AI rewrite step is allowed between review and import.
2. **Whole-row mapping:** for every source occurrence, compare the frozen source/export to the normalized importer input and to a disposable database readback: stem and raw stem, passage fields, all four choice letters and texts, native tables, figure kind and asset identity, source regions, concept and topic tags, numeric difficulty, and explanation fields. A shuffle must preserve the letter-to-content mapping and the verified correct content. Reject any dropped or recomputed field rather than silently filling it.
3. **Answers and holds:** keep the printed official key and independent solve in separate fields. An independently confirmed generated key must keep official fields null and retain both reviews and artifact hashes. Disagreements, missing usable official mappings, source/figure/category/skill uncertainty, withdrawn readiness, incomplete accepted numeric answer sets, or stale versions stay held. Verify both client and server grading for every accepted numeric answer set. D's 1–7 rating remains bound to the exact current content and B solution hashes.
4. **Canonical identity and replay:** resolve G's global exact/near/legacy duplicate decisions and preserve all exam occurrences, source versions, aliases and holds. Run full-batch source-identity and duplicate preflight before the first write. On a disposable database, exact replay must skip without changing content, keys, tags, attempts, responses or mastery; changed source bytes, choice mapping, key evidence, difficulty or version must fail as a conflict.
5. **Private staging and publication:** insert only held, nonlive drafts; verify both student selectors return zero and existing completed/incomplete history is unchanged. Prove a history-safe rollback on the disposable database. Separately verify the actual production Worker/database binding and migration state before any production write. Publication needs the final per-question source, answer, category, figure, math, explanation, duplicate and rendering reviews and an explicit promotion decision.

The present `questions:import-reviewed` non-dry-run uses the shared writer, not the pilot's private-draft mode. Its current readiness checks include source identity and reviewed-difficulty fields, but they do not independently authenticate the final JSON bytes or all A–G file bindings. Do not use it to load the corpus while this gate is open.
