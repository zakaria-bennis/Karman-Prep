# Question figures and account themes

The shared renderer owns theme behavior. Figure authors own the question-specific coordinates, text, curve sampling, source review and versioned files. Do not change source geometry merely to apply a palette.

Native `QuestionTable`, `ChartFigure` and `GeometryFigure` use the same semantic tokens as the UI. Charts preserve series order and legend associations. Student-facing SVGs loaded by `FigureFrame` are inlined only through `sanitizeThemedSvg`: an inert SVG subset with no scripts, HTML, CSS, events, external references, images, filters or animations. IDs/old accessibility references and internal processing metadata are removed; the question's accessible description becomes the SVG label. SVGs need a finite positive `viewBox` and responsive sizing.

CF assets with existing `question_id`, a 64-character hexadecimal `source_version` and `B_output_version` metadata use their known KARMAN palette as semantic paint. New reviewed assets can mark the root `data-figure-theme="karman-v1"` and paint-bearing nodes `data-figure-role="background|surface|shade|text|axis|grid|math|reading|gold|series-1|series-2|series-3|series-4|series-5|series-6"`. Known CF monochrome series colors are mapped consistently within one asset, preserving legend/data associations; more than six distinct such series keep authored colors. Unreviewed SVGs are sanitized but not recolored; raster source images retain their colors and pixels.

The paint tokens are `--figure-background`, `--figure-surface`, `--figure-shade`, `--figure-text`, `--figure-axis`, `--figure-grid`, `--figure-math`, `--figure-reading`, `--figure-gold` and `--figure-series-1` through `-6`. They inherit the selected account theme. Do not bake a single dark background into a new inline figure. No global inversion/filter is applied to source figures.

Keep asset-specific grid opacity and exponential-curve smoothing in the CF asset revision. This renderer does not move their points or add smoothing. Native charts expose `--figure-grid-opacity`; increasing a source opacity by 20% means `min(1, previousOpacity * 1.2)`, and opaque lines cannot be made more opaque. Contrast can instead be improved through the grid token, without claiming an opacity increase.

Cross-origin assets must permit browser CORS reads for inline rendering. Otherwise the accessible image fallback still displays, but its internal paint cannot inherit themes. Verify the actual published asset URL and CORS configuration before deployment; no unrestricted image proxy is introduced. CF/source/editorial holds remain unchanged. A rendering pass does not grant publication approval or verify the question's mathematical content.

The corrected CF curve contract using `var(--karman-figure-ROLE,var(--cf-fallback-ROLE))` is also supported. Its asset stylesheet (including OS-theme fallbacks) is removed; allowlisted paint tokens are mapped to host roles. The surface/shade distinction survives. The curve's grid fallback `0.30` is retained numerically, preserving the approved increase from `0.25`. `--figure-cf-grid` provides its grid paint; Observatory keeps `#d7be89` exactly and other palettes inherit their axis tone. This adapter does not fit or invent an exponential equation.
