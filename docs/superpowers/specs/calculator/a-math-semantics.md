# Calculator: math semantics

Date: 2026-10-16 · Part of the [Karman calculator design](../2026-10-16-calculator-design.md) · Owner: Zakaria Bennis

This file defines what every row means mathematically. It covers how LaTeX from typing, the API, paste and Transfer to Calculator becomes a syntax tree; how a row is classified; how numbers, lists, angles and complex values evaluate and display; what counts as a correct graph; and how points of interest are found. Every rule is a checklist ID with an automated test, and a golden corpus shared with the Transfer tests holds the expected results. Where test-day behaviour was not captured, a rule gives a concrete default and says when REA behaviour capture confirms it. A capture that disagrees with a default changes the rule, its corpus cases and its tests in one pull request.

IDs defined here:

- **PR-1 to PR-45**: input dialects, parsing grammar and precedence, typing outcomes, the golden corpus, member access.
- **RC-1 to RC-21**: row classification, reserved names, collisions and cycles.
- **NM-1 to NM-44**: number display, fractions, real-number domain, complex mode, angle mode, lists, limits and tolerances.
- **G-1 to G-24**: what graphs and what a correct graph is. G-1 and G-3 to G-6 keep their original meaning. G-2 keeps its meaning except that single points moved to G-7, so Phase 1 can test them. G-5 moves to Phase 1 because the zoom and Home controls in L-1 ship in Phase 1.
- **POI-1 to POI-21**: points of interest, labels, trace, draggable points and the label fraction toggle.

IDs referenced from other files: T-1 to T-6, T-13, R-2, R-5 to R-7, S-1, S-9, SC-6, SC-9, K-4, L-1, AN-, A11Y-2, A11Y-11, A11Y- and TH- (e-ux-keypad-accessibility-theme.md); FN-, including FN-47, FN-48, FN-50, FN-57, FN-58 and FN-79, D-1 and D-2 (b-functions-and-data.md); TR-, including TR-7, TR-11, TR-12, TR-14, TR-24, TR-28, TR-31, TR-35, TR-62, TR-67 and TR-73 (c-transfer.md); AR- and API-, including AR-3, AR-58 and API-13 (d-architecture-integration.md).

## 1. Ground rules

- **Target.** Behaviour matches the SAT testing configuration (D2). The test-day calculator is a reference for observable behaviour only. Nothing here copies its code, assets or exact visual design.
- **Scientific calculator.** The Scientific calculator (CB-3) uses these rules; SC-6 adds `ans`, SC-9 adds the ×10ⁿ key for scientific notation, and `e` is Euler's number in both calculators.
- **No earlier engine is a reference.** Only the rules in this file and the test-day calculator's
  observable behaviour are.

**Conventions.**

- _Undefined_ is the single non-value state. It displays as `undefined` (NM-6) and never as NaN or Infinity.
- _px_ means CSS pixels. Graph tests run on an 800×600 px graph area at device pixel ratio 1, in the default view (G-5) unless a rule says otherwise.
- _Tree_ means the canonical syntax tree in the corpus notation (section 2.8).
- _Test kinds_: unit (Vitest, node), component (Vitest, jsdom, with the real MathField), browser (Playwright), visual, contrast, perf.

## 2. Parsing (PR-)

### 2.1 Input paths and dialects

There are three input paths. Typed input comes from the MathField. API and paste input is LaTeX. Question dialect is the KaTeX source of question content that Transfer to Calculator reads; the question style guide (`question-imports/chatgpt/KarmanGPT.txt`, section 16) writes it with `\dfrac`, `\cdot`, `\le`, `\%` and `x_1`.

- **PR-1** Typed, API and paste input go through one normalizer and one parser, so the same math always yields the same tree. Question dialect is first rewritten by the eager TR-7 normalisation in `src/lib/calculator-transfer/` (AR-3); PR-5 and PR-6 state the question-dialect rules that normalisation applies, and the corpus asserts that each question-dialect case and its TR-7 output parse to the same tree, except that a mixed number in a table cell or point coordinate is compared by value, because TR-28 writes it as an improper fraction (PR-6). Math pasted from rendered question content (T-12: the `application/x-tex` annotation, or KaTeX's plain-text copy) is question dialect and goes through TR-7 first, like Transfer; other pasted text is paste input. (Phase 1; verified by unit test)
- **PR-2** For every corpus case with LaTeX input, parsing the LaTeX and parsing the MathField's `latex()` after loading that LaTeX give identical trees. The exception is a hidden built-in name (`\operatorname{argmax}`), which is no MathQuill name, so the field splits it as typing does (`\arg\max`). (Phase 1; verified by component test)
- **PR-3** The normalizer maps `\dfrac` and `\tfrac` to `\frac`; drops `\left`, `\right`, `\displaystyle` and the spacing commands `\,` `\;` `\:` `\!` `\ ` `\quad`; maps `\cdot` and `\times` to explicit multiplication, `\div` to division, `\le` `\leq` `\leqslant` to ≤, `\ge` `\geq` `\geqslant` to ≥, and `\lt` `\gt` to < and >; and maps `\operatorname{n}`, `\mathrm{n}` and `\text{n}` to the operator n when n is on the allowlist (PR-12). (Phase 1; verified by unit test)
- **PR-4** The normalizer maps the Unicode characters − – × · ÷ π θ τ ≤ ≥ ² ³ and the subscript digits ₀ to ₉ to their LaTeX forms, so `x₁` becomes `x_{1}` and `x²` becomes `x^{2}`. (Phase 1; verified by unit test)
- **PR-5** In question dialect, `{,}` between digit groups is removed (`1{,}250` is 1250). In question-dialect math segments, a bare comma is always a separator and is never read as a thousands separator; question table cells follow TR-24. (Phase 1; verified by unit test)
- **PR-6** In question dialect, an integer literal a followed directly by `\frac{b}{c}` with integer literals 0 < b < c is a mixed number when it starts the math or follows an operator, relation, comma or opening bracket. It becomes `\left(a+\frac{b}{c}\right)`, except in table cells and point coordinates, where TR-28 writes the improper fraction (`2\frac{1}{2}` becomes `\frac{5}{2}`). Elsewhere `-2\frac{1}{2}` becomes `-\left(2+\frac{1}{2}\right)`. Typed and API input, and pasted text that is not rendered question math, keep the product meaning: `2\frac{1}{2}` is 1. (Phase 1; verified by unit test)
- **PR-7** Postfix `\%` divides by 100 (`44\%` is 0.44), and `p\%\operatorname{of}q` is p/100·q, in every input path (confirm by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
- **PR-8** As in Desmos, `\degree` (what a typed ° becomes) is the name degree and `^{\circ}` or `^\circ` is a power of the name circ; a raw `°` in LaTeX is `unknown-symbol` ("Sorry, I don't understand the '°' symbol."). There is no degree-sign operator; NM-27 gives the consequences. (Amended 2026-10-21, owner decision: exactly Desmos, appendix F.) (Phase 1; verified by unit test)
- **PR-9** These constructs return a parse error with code `unsupported`, never a partial tree: `\pm`, `\mp`, `\ne`, `\approx`, `\infty` outside integral or sum bounds and the bound arguments of cdf (FN-48, FN-52), `\text{}` holding anything but an allowlisted name, `\begin{…}` environments in every phase (matrix literals are written `[a,b;c,d]` per FN-80 and parse to the head `matrix` from Phase 4), and `\sim` until PR-30 ships in Phase 3. Until the rule that gives them meaning ships, these also return `unsupported`: postfix `!` (NM-15, FN-79; Phase 2); member access `.` after a name (PR-45; Phase 3); list indexing, slicing, filtering and comprehensions (PR-34, deferred by the 2026-10-18 lists package with their own message); `\sum`, `\prod`, `\int`, `\frac{d}{dx}`, primes, `\operatorname{with}`, `\operatorname{and}` and `\operatorname{or}` (PR-28, PR-33, PR-35; Phase 4); and any call to an allowlisted built-in, with or without parentheses (PR-24, PR-25), whose FN- rule has not shipped (confirm `\ne` by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)

### 2.2 Numbers and names

- **PR-10** A number literal is digits with at most one decimal point (`12`, `0.5`, `.5`, `5.`). A sign is never part of a literal. Spaces between digits are ignored as in LaTeX, so `2 3` is 23. Neither calculator has E-notation, so `2e3` is 2·e·3; scientific notation is entered as `\times10^{3}` with the ×10ⁿ key (SC-9). (Phase 1; verified by unit test)
- **PR-11** An identifier is one Latin letter, case-sensitive, or one lowercase Greek letter command other than `\pi`, `\tau` and omicron. It may carry a subscript of letters and digits (`a_{1}`, `x_{12}`, `v_{max}`). Subscripts are compared as written, so `a_{1}` and `a_{01}` are different names. (Phase 1; verified by unit test)
- **PR-12** One allowlist module, `src/lib/calculator/core/latex/operator-names.ts`, lists every built-in operator name and auto-command. It generates the parser's names, MathQuill's `autoOperatorNames` and `autoCommands` (T-3) and the functions panel entries (K-4), and a test asserts that all three match. Member names (`null`, `p`, `pleft`, `pright`, `score`, `dof`, `stderr`, `conf`, `lower`, `upper`, `estimate`) are a separate list in the same module: they generate K-4 panel entries that insert `.name` at the caret, are recognised only directly after `.` (PR-45), and are never parser bare names, PR-13 split targets or MathQuill autoOperatorNames; the three-way match test compares the non-member names, and a corpus case asserts that `3p+4=19` offers a chip for p after category 7 ships. (Phase 1; verified by unit test)
  - _Amended 2026-10-19 (appendix F decision 2, Desmos behaviour wins):_ the allowlist also holds `abs` (category 12) and `length` (category 4), which Desmos accepts as built-in names, so typing them now gives an operator name. Built-ins ship by name through the module's `SHIPPED` set, one task at a time; each entry's `phase` is informational only: no code reads it. The K-4 functions panel lists the names that are in `SHIPPED` and have an entry in `PANEL_PRESENTATIONS` (operator-names.ts), so shipping a name that has a panel entry adds it to the panel at once. Today only trig, inverse trig, exp, ln and log have panel entries.
- **PR-13** A run of Latin letters outside a command is split left to right, taking at each position the longest allowlisted name or auto-command that starts there. This is the rule MathQuill applies while typing (T-3). Letters that start no name are single-letter identifiers multiplied implicitly: `mx` is m·x, `sinx` is sin x and `2pix` is 2πx. (Phase 1; verified by unit test)
- **PR-14** A digit run directly after a single-letter identifier is that identifier's subscript: `x1` is `x_{1}` and `a12` is `a_{12}`. This matches automatic numeral subscripts while typing (T-4). (Phase 1; verified by unit test)
- **PR-15** `e`, `\pi` and `\tau` are the constants e, π and 2π. `i` is the imaginary unit only in complex mode (NM-17). `\theta` is the polar angle. Every other letter is an identifier. `e_{…}` with any subscript is an ordinary identifier distinct from the constant e, so typed `2e3` (T-4 gives `2e_{3}`) is 2·e₃ with an add-slider chip for e₃. (Phase 1; verified by unit test)

### 2.3 Operators and precedence

| Level (loosest first) | Operators                                                                             | Grouping                                  |
| --------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------- |
| 1                     | `\operatorname{with}`                                                                 | right side is a comma list of definitions |
| 2                     | `,` in lists, points, arguments and piecewise branches                                | separator                                 |
| 3                     | `\operatorname{or}`                                                                   | left to right                             |
| 4                     | `\operatorname{and}`                                                                  | left to right                             |
| 5                     | `=` `<` `>` `\le` `\ge` `\sim`                                                        | chains, see PR-29                         |
| 6                     | `+` and binary `-`                                                                    | left to right                             |
| 7                     | `\cdot` `\times` `/` `\div` and implicit multiplication                               | left to right, one shared level           |
| 8                     | unary `-` and `+`                                                                     | prefix                                    |
| 9                     | built-in function without parentheses                                                 | prefix, argument by PR-24                 |
| 10                    | `^`, postfix `!` `\%`, prime `'`                                                      | `^` right to left; postfix on one atom    |
| 11                    | numbers, names, groups, `\frac`, roots, bars, lists, calls, member access `.` (PR-45) | atoms                                     |

- **PR-16** Operators bind as the precedence table says. (Phase 1; verified by unit test)
- **PR-17** Unary minus binds looser than `^` and `!`: `-x^{2}` is −(x²), `-2^{2}` is −4, `(-2)^{2}` is 4 and `-3!` is −6. (Phase 1; verified by unit test)
- **PR-18** Implicit and explicit multiplication and division share one level and group left to right, so raw `6\div2(1+2)` is 9 and raw `1/2x` is x/2. Typed `1/2x` builds `\frac{1}{2x}` (T-2), which is 1/(2x) (confirm by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
- **PR-19** Exponents come from structure: `^{…}` holds the exponent. Raw `^` without braces takes the next single character or command, as in LaTeX, so `x^23` is x²·3. `a^{b^{c}}` nests to the right, and a raw double superscript `a^b^c` is a parse error. (Phase 1; verified by unit test)
- **PR-20** Postfix `!` and `\%` apply to the atom just before them, including a superscripted atom: `x^{2}!` is (x²)!, `2x!` is 2·(x!) and `3!^{2}` is 36. Until NM-15 ships in Phase 2, `!` returns `unsupported` (PR-9), so the `!` cases here and in PR-17 run from Phase 2. (Phase 1; verified by unit test)
- **PR-21** Typed absolute-value bars arrive as `\left|…\right|`. In raw input a `|` opens a bar when it follows the start, an operator, a relation, `(`, `[`, `\{`, `,` or another opening bar, and closes one otherwise. The cases `|x|-|y|`, `||x|-1|` and `2|x-3|` parse as written. (Phase 1; verified by unit test)
- **PR-22** Parentheses holding exactly two top-level comma-separated parts form a point. One part is a group, and three or more parts are a parse error. A comma where no bracket takes one, at the end of the row or of a braced argument (`1,000`, `\sqrt{4,9}`), is Desmos's "Points are written like this: (1, 2)." (_amended 2026-10-20, captured 2026-10-19_). (Phase 1; verified by unit test)

### 2.4 Functions

- **PR-23** `n(…)` is a call only when n is a built-in name, or a single-letter identifier (optionally subscripted) that some row defines as a function, in any row order (G-6). Otherwise it is implicit multiplication: `a(x-h)^{2}+k` is a·(x−h)²+k, and `f(2)` with no definition of f is f·2. (Phase 1; verified by unit test)
- **PR-24** Without parentheses, a built-in function's argument is the run of implicitly multiplied factors after it (numbers, names, constants, powers, groups, fractions, roots and absolute values), including a leading unary minus. It ends before `+`, binary `-`, `\cdot`, `\times`, `/`, `\div`, a relation, `,`, `:`, a closing bracket or another built-in name. So `\sin2x` is sin(2x), `\sin x+1` is sin(x)+1, `\ln x^{2}` is ln(x²), `\sin2\pi x` is sin(2πx), `\sin-x` is sin(−x) and `\sin x\cdot2` is 2·sin(x) (confirm by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
  - _Amended 2026-10-19 (appendix F decision 2, Desmos behaviour wins):_ only the circular and hyperbolic trig names, their inverses, ln and log take an argument without parentheses (`PREFIX_FORM_NAMES`). Any other built-in written without `(` is the `function-parentheses` error "'floor' is a function. Try using parentheses." (`\operatorname{floor}2.5`, `\operatorname{sign}-3`, `\operatorname{floor}` on its own), as in Desmos. A prefix-form name alone at the end of the row reads as Desmos's empty call, "Function 'sin' requires an argument. For example, try typing: sin(x)." exp needs `(` as in Desmos (captured by the 2026-10-19 review): `\exp 2`, `\exp^{2}(1)` and `\exp` on its own each read "'exp' is a function. Try using parentheses.", and `\exp()` reads "Function 'exp' requires an argument. For example, try typing: exp(x)." A run followed by another built-in call (`\sin 2\cos 1`, `\sinh 2\cosh 1`) is the `argument-parentheses` error "Use parentheses around the argument of 'sin'.", as in Desmos; a run that is only a built-in call (`\sin\cos x`) is still read as nesting.
- **PR-25** When `(` directly follows a built-in name, that group alone holds the arguments: `\sin(x)y` is sin(x)·y and `\sin(x)^{2}` is (sin x)². (Phase 1; verified by unit test)
- **PR-26** A superscript between a function name and its argument raises the result to that power: `\sin^{2}x` is (sin x)² and `\ln^{2}x` is (ln x)². The exception is `^{-1}` on the six circular and six hyperbolic trig names, which means the inverse function: `\sin^{-1}x` is arcsin x and `\cosh^{-1}x` is arcosh x. On `log` and `ln` the only power allowed is `^2`; any other (`\ln^{-1}x`, `\log^{3}x`) is Desmos's error "Only ln^2 is supported. Otherwise, use parens." (or log^2). On any other built-in, `^{-1}` is the reciprocal of the result. (Phase 1, log and ln powers from the Desmos function catalogue 2026-10-19; verified by unit test)
  - _Amended 2026-10-19 (appendix F decision 2, Desmos behaviour wins):_ `^{-1}` on an inverse trig or inverse hyperbolic name is the forward function, as in Desmos: `\arcsin^{-1}(0.5)` is sin(0.5) and `\operatorname{arcsinh}^{-1}(2)` is sinh 2. A power on the name of a built-in outside PR-24's prefix-form names (`\operatorname{floor}^{2}(2.5)`, `\operatorname{abs}^{-1}(2)`) is the `function-parentheses` error, not a power or reciprocal.
  - _Amended 2026-10-19 (appendix F decision 2, Desmos behaviour wins):_ on the twelve circular and hyperbolic trig names and their inverses the only powers allowed are `^2` and `^{-1}`; any other (`\sin^{3}(1)`, `\sin^{-2}(1)`, `\sin^{0.5}(1)`) is "Only sin^2 and sin^-1 are supported. Otherwise, use parens." (with that name), read after the argument, so `\sin^{-1x}` is still the missing-argument error (function catalogue, captured live).
  - _Amended 2026-10-20 (appendix F decision 2, Desmos behaviour wins):_ the allowed powers are the literal tokens, as Desmos's parser compares them: the digit `2` alone, or a minus sign before the digit `1` alone. `\sin^{2.0}(1)`, `\sin^{02}(1)`, `\sin^{(2)}(1)`, `\sin^{-1.0}(0.5)` and `\log^{2.0}(3)` are the power errors (from Desmos's parser source).
- **PR-27** `\log x` is base 10, `\log_{b}x` is base b and `\ln x` is natural. A base is written only as a subscript: `\log(x,b)` and `\log_{b}(x,y)` are RC-20's arity error, shown as "log takes only 1 input, like log(x).", and an empty subscript `\log_{}(x)` shows "The subscript is empty." (which errors occur: Desmos function catalogue, 2026-10-19; the text is Karman's, section 2.8). Only `log` takes a subscript: one on `ln` or a trig or hyperbolic name, empty or not and before or after a power, shows "ln can't have a subscript." (with that name; captured for `\ln_{2}(8)`, the rest from Desmos's parser, which checks a subscript on these names first). `\sqrt{x}` is the square root and `\sqrt[n]{x}` is the nth root; NM-11 gives its domain. (Phase 1; verified by unit test)
- **PR-28** Calculus syntax: `f'(x)` and `f''(x)` differentiate a defined one-parameter function. `\frac{d}{dx}` takes its argument by the PR-24 rule. `\int_{a}^{b}…dx` takes everything up to its trailing differential and is a parse error without one. `\sum_{n=a}^{b}` and `\prod_{n=a}^{b}` take their argument by the PR-24 rule, with n local. (Phase 4; verified by unit test)

### 2.5 Relations and conditions

- **PR-29** The relations are `=`, `<`, `>`, `\le` and `\ge`. A chain that mixes `=` with `<`, `>`, `\le` or `\ge` (`x=y<3`) is a parse error, Desmos's "Cannot mix inequalities and equations in a chain of comparisons.", and so is a relation operator straight after another (`x=>1`: "You need something on both sides of the '>' symbol.", naming the second). Other chains parse and evaluate link by link, in conditions too (`\{1=1=1:5\}` is 5); a graphed chain follows RC-14. (Phase 1; verified by unit test)
- **PR-30** `\sim` (or a typed `~`) may appear once, at top level, with an expression on each side. It means a regression (D-2) and parses to `(sim L M)`; a second `\sim`, one inside parentheses or one beside a relation is `syntax`, and one with a side missing is `sim-side` (a half-typed regression), whose message is appendix F's "You need something on both sides of the '∼' symbol."; neither is `unsupported`. (Phase 3, built in the parity work; verified by unit test)
- **PR-31** `\{c_1:v_1,c_2:v_2,…,v\}` is piecewise: the value of the first true condition is used, and the optional final bare value is the otherwise case. With no otherwise case and no true condition the result is undefined. `\{c\}` alone is 1 when c is true and undefined otherwise. As in Desmos, a part with no `:` is a condition whose value is 1, `\{\}` is 1, a condition with a list operand broadcasts every part (NM-33), and the parse errors are Desmos's (appendix F). (Phase 2; verified by unit test)
- **PR-32** Condition braces directly after an expression or relation restrict it, as in `y=x^{2}\{x>0\}`. Several restrictions combine with and, as in `\{0<x<2\}\{y>1\}`, and the row is undefined wherever any restriction is false or undefined. As in Desmos, a restriction is multiplication by a piecewise, so `y=x\{x>0\}` is `(rel = (id y) (mul (id x) (piecewise (if (rel > (id x) (num 0))))))` and the `restrict` head is never produced. (Phase 2; verified by unit test)
- **PR-33** Inside conditions, `\operatorname{and}` binds tighter than `\operatorname{or}`, and both bind looser than relations. (Phase 4; verified by unit test)

### 2.6 Lists and substitution

- **PR-34** List syntax covers `[a,b,c]`, `[]`, the ranges `[a...b]` and `[a,b,...,c]` (`\ldots` is accepted for `...`), indexing `L[i]`, slicing `L[i...j]`, filtering `L[c]` with a condition c, and comprehensions `[e\operatorname{for}n=L,m=M]`, whose loop names are local to the brackets. NM-30 to NM-38 give the meaning. A range has one or two items before the ellipsis and one after it, with an optional comma on either side of the ellipsis; any other shape is `syntax`. A `[` directly after a name, a call, a list, a number or another index is indexing, as in Desmos: `5[1]` reads "Cannot index a number with a number." and `L[]` "Square brackets cannot be empty." (2026-10-19 capture; `2[1,2]` no longer multiplies). Inside the brackets a range side may be empty (`L[2...]`, `L[...3]`, `L[...]`), and one relation, which may be a chain, is a filter (`L[2<L<6]`). Literals, ranges, indexing, slicing and filtering ship; until NM-37 ships, comprehensions are `unsupported` row errors that name the notation, "Building a list with 'for' isn't supported yet." (R-2). (Phase 2; verified by unit test)
- **PR-35** `e\operatorname{with}a=1,b=2` substitutes the listed definitions into e only, at the loosest precedence. (Phase 4; verified by unit test)

### 2.7 Typing outcomes (MathQuill configuration)

The MathQuill settings belong to T-1 to T-4. This file fixes the LaTeX and trees those settings must produce, so a configuration change that alters parsing fails a test here.

- **PR-36** Keystroke cases run through the real MathField produce these results. `y=x^2`, right arrow, `+3/4` gives `y=x^{2}+\frac{3}{4}`, as observed on 2026-10-16. `x^2+1` with no arrow gives `x^{2}+1` (T-6), and `e^-x` gives `e^{-x}` (T-1). `3x/4` gives `\frac{3x}{4}` (T-2). `y=sqrtx`, right arrow, `+pi` gives `y=\sqrt{x}+\pi`, as observed. `x1` gives `x_{1}`, `2e3` gives `2e_{3}` (T-4, PR-15), `<=` gives `\le`, `sinx` gives `\sin x`, and `mx` stays two identifiers. (Phase 1; verified by component test)
- **PR-37** The parser's printer turns any tree back into canonical MathQuill LaTeX, and parsing that output returns the same tree. Transfer to Calculator writes the TR-7 normalised LaTeX, which PR-44 checks parses to its corpus tree, and printer output is used only for the TR-35 duplicate check. (Phase 1; verified by unit test)

### 2.8 Syntax tree and errors

- _Error copy (owner decision, 2026-10-21):_ every user-facing error and warning, in rows, table cells and headers, slider limits and regressions, uses Karman's own short plain-English text (`src/lib/calculator/core/analysis/messages.ts`, about eight words at most, an example only where it helps, no "Error:" or "please"). Where this spec quotes Desmos's text, the quote identifies which error occurs; the shown text is its Karman translation (the test fixture `core/analysis/__fixtures__/desmos-copy.ts` maps one to the other, and the reference parity tests compare through it). For example `\operatorname{nCr}(5)` reads "nCr needs 2 inputs, like nCr(1, 2)." and `y=mx+b` "m and b are not defined." (verified by unit test)

The corpus writes trees as S-expressions. The heads are `num`, `id`, `const`, `add`, `sub`, `neg`, `mul`, `div`, `pow`, `fact`, `pct`, `deg`, `abs`, `root`, `call`, `member`, `point`, `list`, `matrix`, `range`, `index`, `for`, `with`, `piecewise` (each part `(if C V)` or `(if C)`, then the otherwise value), `restrict` (never produced, PR-32), `rel`, `and`, `or`, `sim`, `prime`, `deriv`, `int`, `sum` and `prod`. `\frac` and `/` both give `div`. For example, `y=mx+b` is `(rel = (id y) (add (mul (id m) (id x)) (id b)))`. Classification (section 3) is a separate field.

- **PR-38** Parsing never throws. It returns a tree or an error with a code and the source span, and R-2 turns the code into a plain-language message. (Phase 1; verified by unit test)
- **PR-45** Member access: an atom (a name or a call) whose value is a distribution or an inference test, followed directly by `.` and a PR-12 member name or one of `pdf`, `cdf`, `random`, forms `n.m` or `n.m(args)` at level 11, parsing to the head `member` (`(member (id T) score)`); this gives FN-47, FN-48, FN-50, FN-57 and FN-58 their `D.pdf(x)`, `D.cdf(…)`, `D.random(n)` and `T.score` forms; a member on any other value or an unknown member is a row error, and until Phase 3 a `.` after a name returns `unsupported` (PR-9). _Amended 2026-10-20:_ the coordinates `P.x` and `P.y` ship in Phase 2: after a name, call, list, point, index or `(…)` group (`((1,2)+(3,4)).x`), `.x`, `.y` or `.z` reads a point's coordinate, element by element on a list of points (`L.x`), with Desmos's errors "Cannot access coordinate '.x' of a number." and "Cannot access coordinate '.z' of a 2d point."; another lone letter (`P.X`) reads "Sorry, I don't understand the way that '.' is used here." (captured 2026-10-19). (Phase 3; verified by unit test)

| ----------------------------------- | ------------------------------------------------------------- |

| `x=y^{2}`                           | explicit curve x=g(y)                                         |
| `2x+3y=12`, `x^{2}+y^{2}=25`        | implicit curve                                                |
| `2x+5=17`, `x^{2}=4`                | vertical lines at x=6; at x=−2 and x=2                        |
| `y>2x+1`, `x\le3`, `1<y<3`          | shaded region                                                 |
| `x^{2}`                             | curve y=x²                                                    |
| `3+4`                               | value 7                                                       |
| `a=3`                               | definition of a with value 3; slider-eligible (R-7)           |
| `a=2x`, `A=\pi r^{2}`               | dependent definition; not graphed                             |
| `C=8h+15`                           | definition of C; add-slider chip for h                        |
| `y=ax+b`                            | chips for a, b and all; nothing graphed (observed 2026-10-16) |
| `3p+4=19`, `3p+4<19`                | chip for p; nothing graphed                                   |
| `f(x)=x^{2}`, `P(t)=500(1.03)^{t}`  | function definition; graphed against the horizontal axis      |
| `g(a,b)=a+b`                        | function definition; not graphed                              |
| `f(2)` with f defined / not defined | value / product f·2 with a chip for f                         |
| `a(x-h)^{2}+k`                      | product; chips for a, h and k                                 |
| `(1,2)`                             | point                                                         |
| `(\cos t,\sin t)`                   | parametric curve                                              |
| `r=2\sin\theta`                     | polar curve                                                   |
| `2<3`                               | whole view shaded                                             |
| `x+y`, `e=2`, `a=a+1`               | error                                                         |
| `y_{1}\sim mx_{1}+b`                | regression (D-2)                                              |

- **RC-1** Names are case-sensitive, so `A` and `a` are different names. (Phase 1; verified by unit test)
- **RC-2** A row takes the first rule that matches, in this order: empty; table (D-1); regression with `\sim` (D-2); function definition (RC-4); definition of a name (RC-6); relation (RC-11 to RC-14); point or parametric curve (RC-15, RC-16); bare expression (RC-17). Until RC-16 and RC-18 ship in Phase 2, a point whose parts depend on a `t` that no row defines, and any row other than an RC-6 definition that uses `r` or `\theta` (including the `r=…` and `\theta=…` rows of RC-19), give a row error with code `unsupported` (R-2); `A=\pi r^{2}` stays a dependent definition (RC-6). (Phase 1; verified by unit test)
- **RC-3** The reserved names are `x` and `y` (coordinates), `r` and `\theta` (polar), `e`, `\pi`, `\tau`, `i` in complex mode, and every built-in name. `t` is the parametric parameter only inside a point whose `t` no row defines. (Phase 1; verified by unit test)
- **RC-4** `f(p_1,…,p_n)=body` defines a function when f is a single non-reserved letter (optionally subscripted) and the parameters are 1 to 8 distinct single letters; x, y and t are allowed as parameters. Parameters are local and shadow other names. (Phase 1; verified by unit test)
- **RC-5** A one-parameter definition graphs as y = f(p) against the horizontal axis, whatever the parameter is called (`f(x)=x^{2}`, `P(t)=500(1.03)^{t}`, `h(y)=y+1`). Definitions with two or more parameters are not graphed (confirm by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
- **RC-6** `n=expr`, with n a single non-reserved name, defines n. The row shows n's value when expr evaluates to a number, point or list (a literal point or list of literal points excepted, RC-15). When expr depends on x, y, r or θ the definition is dependent: it is not graphed, and other rows may use it. So after `a=2x`, the row `y=a` graphs y=2x, and `A=\pi r^{2}` defines A in terms of the polar r (confirm by REA behaviour capture in Phase 1). A definition whose value is a point or a list of points (`A=(1,2)`, `P=[(1,2),(3,4)]`) also draws its points, as Desmos does (_amended 2026-10-20, M5, captured 2026-10-19_). (Phase 1; verified by unit test)
- **RC-7** A name defined in more than one row, as a value, function, list or table column, puts an error on every defining row, and rows that use the name show a dependency error. A defining row reads "You've defined 'm' in more than one place. Try deleting some of the definitions of 'm'." (appendix F's text, with the name as R-2 shows it), and a row that uses the name reads "m has more than one definition.". (Phase 1; verified by unit test)
- **RC-8** A definition cycle puts an error on every row in the cycle. This covers self-reference (`a=a+1`), mutual reference (`a=b` with `b=a`) and recursion through functions; recursive functions are not supported. (Phase 1; verified by unit test)
- **RC-9** Definitions resolve in any row order, and hidden rows still define their names; hiding affects only the graph. (Phase 1; verified by unit test)
- **RC-10** Names that are used but neither defined, reserved nor built in become add-slider chips (the buttons of R-6's `add slider:` line) in order of first appearance, with `all` added when there are two or more. The row graphs nothing until they are defined. A chip adds the row `n=1` with bounds −10 ≤ n ≤ 10 and no step (R-7). (Phase 1; verified by unit test)
- **RC-11** A relation with exactly `y` on one side and no `y` on the other is an explicit curve y=f(x). Exactly `x` on one side gives x=g(y). `y=c` and `x=c` are horizontal and vertical lines. (Phase 1; verified by unit test)
- **RC-12** Any other equation in x and y is an implicit curve. An equation in x alone is the set of vertical lines at its real solutions in view (`2x+5=17` is x=6 and `x^{2}=4` is x=±2), and an equation in y alone gives horizontal lines. (Phase 1; verified by unit test)
- **RC-13** An equation or inequality whose only free names are not coordinates is not solved: `3p+4=19` and `3p+4<19` each offer a chip for p and graph nothing (confirm by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
- **RC-14** An inequality in x, y or both is a shaded region (G-17). A chain in x or y graphs only as a double inequality solved for x or y pointing one way (`1<y<x`); otherwise it is Desmos's "This calculator cannot plot chained equations." (`x=y=3`), "This calculator cannot plot chains of more than 2 inequalities.", "We only support solved double inequalities. Try deleting one side of the inequality." (`x<1<2`, a middle that is not x or y or sides that use it) or "Double inequalities must both go the same way, e.g. 1 < y < 2." (`1<y>0`). An inequality or equation with no free names draws nothing and is not graphable, whether or not it holds, as Desmos does (`1<2`, `2<1`, `1<2<3`; break corpus, 2026-10-20). (Phase 1; verified by unit test)
- **RC-15** A point `(a,b)` whose parts evaluate to numbers is a point, and so is a piecewise whose every value is a point (`\{a>0:(1,2),(3,4)\}`) and a point times a restriction (`(1,2)\{a>0\}`, PR-32), and any row whose value is a point or a list of points by its operands' types: point arithmetic (`(1,2)+(3,4)`, NM-32), midpoint (FN-71), and a name or index that holds points (`P`, `P[2]`; _amended 2026-10-20, M4, M5_), and a user call whose body gives one (`f(3)` after `f(a)=(a,2a)`). Such a row also shows its value (R-5), as Desmos does, except a literal point or a list of literal points, whose coordinates are numerals (`(2,3)`, `[(1,2),(3,4)]`, and the body of `A=(1,2)`), which shows none (_amended 2026-10-20, geometry captures 2026-10-19_). A point that uses x or y, in its condition too, is the error Desmos gives as "Too many variables, I don't know what to do with this.", shown as Karman's "Too many unknown variables." (section 2.8). (Phase 1; verified by unit test)
- **RC-16** A point whose parts depend on a `t` that no row defines is a parametric curve. (Phase 2; verified by unit test)
- **RC-17** A bare expression with no free names shows its value. One in x alone graphs as y equal to the expression, and one in y alone graphs as x equal to it. One in both x and y is an error. One that uses r or θ and neither x nor y, such as `2\pi r` or `\sin\theta`, is an error that names r or θ, while `C=2\pi r` stays an RC-6 dependent definition; the corpus has a case for each (confirm by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
- **RC-18** A relation in `r` or `\theta` with no x or y is polar (G-19). In a row that mixes r or θ with x or y, r is √(x²+y²) and θ is the angle of (x, y) in (−π, π] (confirm by REA behaviour capture in Phase 2). (Phase 2; verified by unit test)
- **RC-19** Defining a reserved name is an error, with three exceptions: `x=…` and `y=…` are graphs (RC-11), `\theta=…` and an `r=…` whose right side uses θ are polar (RC-18), `r=…` without θ defines r like any name, and `r(x)=…` defines a function r, after which other rows use r as that value or function (`r=\sqrt{169}`, `6+qr`; `s(x)=r(x)+1`), while a constant `r=c` still draws its polar circle x²+y²=c² (_amended 2026-10-25, live Desmos_), `t=2` defines t, after which `(t,t^{2})` is a point (confirm by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
- **RC-20** A call with the wrong number of arguments is an error that names the expected count. (Phase 1; verified by unit test)
  - _Amended 2026-10-19 (appendix F decision 2, Desmos behaviour wins), wording amended 2026-10-21 (owner decision, section 2.8):_ which calls are arity errors follows Desmos, captured live; the text shown is Karman's. A function that accepts one argument and is given none "needs an input" ("sin needs an input, like sin(x)."), so an empty `()` on a fixed-arity built-in is this error rather than a syntax error. A function taking at most one argument and given more "takes only 1 input" ("floor takes only 1 input, like floor(x)."). Any other function given too many names its largest accepted count, and given too few its smallest count above 1: "nCr needs 2 inputs, like nCr(1, 2).", and likewise mod(1,2,3), arctan(1,2,3) and round(1,2,3) "need 2 inputs". `log` reads as a one-argument function ("log takes only 1 input, like log(x)."), since Desmos writes its base only as a subscript. A user function uses the same wording: with `f(x)=x`, `f(1,2)` reads "f takes only 1 input, like f(x).". The error's names are the function, the expected count and the given count.
- **RC-21** After `setBlank()` (API-) for a new question, nothing from the previous question resolves: no name, slider, function, table column or viewport. Classification starts from an empty scope (R10, AR-58). The student's preferences carry to the new question for the page session (S-9, owner decision 2026-10-21), so the angle mode and complex mode are the ones the student last chose (radians and complex off on a first calculator); the others carried (grid, axes, display size, contrast and the rest) change no parsing, classification, evaluation or display text. (Phase 1; verified by browser test)

## 4. Numbers (NM-)

### 4.1 Display

- **NM-1** A numeric result shows at most 12 significant digits, rounded as JavaScript `toPrecision(12)` rounds. Trailing zeros are trimmed and −0 shows as 0, so `\frac{1}{3}` shows 0.333333333333 and `\pi` shows 3.14159265359 (confirm the digit count by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
- **NM-2** A value with 10^-6 ≤ |v| < 10^12 shows as a plain decimal. Any other non-zero value shows as m×10^n with 1 ≤ |m| < 10 and at most 12 significant digits in m, so `2^{40}` shows 1.09951162778×10^12 (confirm the thresholds by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
- **NM-3** No global or relative epsilon snaps a result to zero. `10^{-20}` shows 1×10^-20; `0.1+0.2` shows 0.3 only because of NM-1 rounding; and `0.1+0.2-0.3` shows 5.55111512313×10^-17. (Phase 1; verified by unit test)
- **NM-4** In radian mode, a circular trig argument within 4 units in the last place of k·π/12, for an integer |k| ≤ 2^20, is evaluated as exactly 15k degrees by NM-26. So `\sin\pi` is 0, `\cos\frac{\pi}{2}` is 0, `\tan\frac{\pi}{4}` is 1 and `\tan\frac{\pi}{2}` is undefined. (Phase 1; verified by unit test)
  - _Amended 2026-10-19 (appendix F decision 2, Desmos behaviour wins):_ Desmos is exact only at quarter turns. When the radian argument r is a double equal to a whole multiple of π computed in doubles (round(r/π)·π = r, |r| ≤ 10^12), sin and tan are 0 and csc and cot undefined; when 2r equals an odd multiple of π the same way, cos and cot are 0 and tan and sec undefined. Every other argument uses the library's sin, cos and tan, and csc, sec and cot are their reciprocals (cot = 1/tan). So `\sin\pi` is 0, `\cos\frac{\pi}{2}` is 0 and `\tan\frac{\pi}{2}` is undefined, but `\sin\frac{\pi}{6}` is 0.49999999999999994, `\tan\frac{\pi}{4}` is 0.9999999999999999 and `\operatorname{floor}(\tan(\frac{\pi}{4}))` is 0 (function catalogue, captured live; checked exactly).
  - _Amended 2026-10-20 (appendix F decision 2, Desmos behaviour wins):_ complex sin, cos, tan, sinh, cosh and tanh build their real and imaginary parts from the same exact sin, cos and tan (tan +∞ at an odd quarter turn, where tanh(a + bi) is (1/tanh a, 0)), so `\cosh(\frac{\pi}{2}i)` and `\coth(\frac{\pi}{2}i)` are 0 and `\sin(\pi+i)` is purely imaginary (function catalogue, captured live for cosh, tanh, sech and coth).
- **NM-5** A point shows as `(a, b)`, each coordinate formatted by NM-1 and NM-2. (Phase 1; verified by unit test)
- **NM-6** Any non-finite result, and any non-real result in real mode, shows the single text `undefined` and never NaN or Infinity. (Phase 1; verified by unit test)
- **NM-7** The fraction form of the decimal/fraction toggle (R-5), as Desmos computes it (captured from live Desmos 2026-10-21, 238 values): for a finite real v, the denominator limit is L = 10^6/√|v|; with L < 1 (|v| > 10^12) or L > 10^12 (|v| < 10^-12) there is none. Otherwise p/q is the last convergent of v's continued fraction (floor terms, computed in doubles on the signed value) whose denominator is at most L, and v has the fraction form p/q when q ≥ 2 and adding |p/q − v|/8 to v leaves v unchanged. The form is an improper fraction with the sign in front of the bar (5/2, −1/8), never mixed, and never changes the stored value. So 0.3 is 3/10, `0.1+0.2` is 3/10, the doubles of 2/3 and 355/113 are 2/3 and 355/113, 1.5×10^-7 is 3/20000000 but −1.5×10^-7 has none (the signed arithmetic, as in Desmos), and a typed 0.666666666667 or 3.14159292035, integers, π, √2 and e have none. (Phase 2; verified by unit test against the captured values)
- **NM-8** Axis numbers label ticks spaced at 1, 2 or 5 times a power of 10. Each label uses the fewest decimals its step needs (a step of 0.2 labels 0.2, 0.4, 0.6; a step of 5,000 labels 5000, 10000) and switches to the NM-2 form outside NM-2's plain range. (Phase 1; verified by unit test)
- **NM-9** Display rounding affects only text. Evaluation, conditions, list operations and regressions use the full double value. (Phase 1; verified by unit test)

### 4.2 Real-number domain

- **NM-10** For a negative base a and a real exponent b, the result is real when b equals p/q in lowest terms with q odd and q ≤ 99. The rational form comes from the tree when the exponent is a fraction of integer literals, and otherwise from the value, using the smallest such q with |b − p/q| ≤ 4 ulp(b). The result is (−1)^p·|a|^b. Otherwise the result is undefined in real mode. So (−8)^{1/3} is −2, (−8)^{2/3} is 4, (−8)^{−1/3} is −0.5, (−32)^{0.2} is −2, and both (−8)^{0.5} and (−2)^{π} are undefined (confirm decimal exponents by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
- **NM-11** `\sqrt[n]{x}` with odd integer n gives the real root of a negative x (`\sqrt[3]{-27}` is −3). With even n it is undefined for x < 0. A non-integer n means x^{1/n} under NM-10. (Phase 1; verified by unit test)
- **NM-12** These are undefined: division by zero, ln and log of zero or a negative number, a log base that is not positive or equals 1, even roots of negatives, arcsin and arccos outside [−1, 1], and trig values at their poles. (Phase 1; verified by unit test)
- **NM-13** 0^0 is 1 (confirm by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
- **NM-14** A result whose magnitude exceeds the largest double is undefined (`10^{400}`); a result that underflows is 0 (`10^{-400}`). (Phase 1; verified by unit test)
- **NM-15** x! is Γ(x+1) and is undefined at negative integers: 0.5! is 0.886226925453, 170! is finite and 171! is undefined. (Phase 2; verified by unit test)
- **NM-16** The sampled curves for `y=x^{1/3}` and `y=x^{2/3}` include points at x = −4, and `y=x^{2/3}` matches `y=\sqrt[3]{x^{2}}` within 0.5 px for x < 0. (Phase 1; verified by unit test)

### 4.3 Complex mode

- **NM-17** With complex mode off, `i` is an ordinary name, exactly as any other undefined name in Desmos: `2i` shows "Add y= at the start." (Karman's text for Desmos's "Try adding 'y=' to the beginning of this equation.", section 2.8) with an add-slider chip for i, and a lone `i` offers no slider. There is no complex-mode hint (amended 2026-10-21, owner decision: exactly Desmos, appendix F). (Phase 1; verified by unit test)
- **NM-18** With complex mode on, `i` is the imaginary unit, and arithmetic, powers, roots, exp, ln, log, trig and hyperbolic functions accept complex values using principal branches. Ln z has imaginary part in (−π, π]; √z has a non-negative real part, and a negative radicand takes the principal root even for an odd index (`\sqrt[3]{-8}` is 1 + 1.732i, as in Desmos; NM-11's real root is real mode only); z^w is e^{w·Ln z}; inverse trig and inverse hyperbolic functions use the principal branches of C99 `casin` and its companions. (Phase 1; verified by unit test)
- **NM-19** Complex mode never changes a value that real mode defines. (−8)^{1/3} is −2 in both modes, while (−8)^{1/2} is 2.82842712475i and `\sqrt{-4}` is 2i only in complex mode (confirm by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
- **NM-20** A complex result shows as a+bi, each part formatted by NM-1 and NM-2. A part with |part| ≤ 10^-14·|other part| shows as 0 and is omitted, so e^{iπ} shows −1, and a unit imaginary part shows as `i`, not `1i`. (Phase 1; verified by unit test)
- **NM-21** In complex mode a curve point is plotted only where its value is real, meaning |Im| ≤ 10^-12·max(1, |Re|); the real part is plotted. (Phase 1; verified by unit test)
- **NM-22** A relation or condition with a non-real operand is false. min, max, sort and other ordering functions return undefined for non-real input. (Phase 1; verified by unit test)
- **NM-23** The Complex functions category (R3; K-4 places it between Matrices and Advanced, and FN-84 to FN-87 define its functions) works in complex mode: real(z) and imag(z) return the real and imaginary parts, conj(z) returns the conjugate, arg(z) returns the angle in radians in (−π, π] in both angle modes, and |z| returns the modulus (confirm arg's unit by REA behaviour capture in Phase 4). (Phase 4; verified by unit test)

### 4.4 Angle mode

- **NM-24** Radians is the default (D5) for a student's first calculator of the page. The S-1 setting switches to degrees, and the student's angle mode carries to the next question's calculator for the page session, like the other S-9 preferences (owner decision, 2026-10-21). (Phase 1; verified by browser test)
- **NM-25** Degree mode changes only the inputs of sin, cos, tan, csc, sec and cot, the outputs of their inverses (including two-argument arctan) and polar θ (G-19). Hyperbolic functions, exp, ln, complex exponentials, arg, derivatives and integrals are unaffected; derivatives of degree-mode trig include the π/180 factor because the function does. A non-real argument (complex mode) is always in radians, whatever the angle unit (FN-18). (Phase 1; verified by unit test)
- **NM-26** In degree mode the argument is reduced exactly modulo 360 (IEEE remainder, exact for doubles) before conversion. Multiples of 90 give exactly 0 or ±1, multiples of 30 give exactly ±0.5 for sin and cos, and multiples of 45 give exactly ±1 for tan and cot. tan at odd multiples of 90, cot at multiples of 180, and sec and csc at their poles are undefined. So sin 30 is 0.5, cos 90 is 0, sin 180 is 0, tan 45 is 1, cos 60 is 0.5, sin 3630 is 0.5 and tan 90 is undefined. (Phase 1; verified by unit test)
  - _Amended 2026-10-19 (appendix F decision 2, Desmos behaviour wins):_ a degree argument is multiplied by π/180 and then follows NM-4, with no reduction modulo 360 and no table: sin 30 is 0.49999999999999994, cos 60 is 0.5000000000000001, tan 45 is 0.9999999999999999 and sin 3630 is 0.5000000000000004, while sin 90 is 1, cos 90 and cos 270 are 0, sin 180 is 0 and tan 90 is undefined (function catalogue, captured live).
- **NM-27** The degree sign converts nothing: as in Desmos, `\degree` and `\circ` are ordinary names (PR-8), in either angle mode. `\sin(30\degree)` shows "Add y= at the start." with an add-slider button for degree (shown as °), `y=\sin(x\degree)` reads "degree is not defined." (Karman's text for Desmos's "Too many variables. Try defining 'degree'.", section 2.8), and with a row `\degree=3` it is sin 90; `30^{\circ}` with `\circ=2` is 900. Angles in degrees use degree mode (NM-26). (Amended 2026-10-21, owner decision: exactly Desmos, appendix F; replaces the earlier degree conversion.) (Phase 1; verified by unit test)
- **NM-28** Inverse trig ranges: arcsin [−π/2, π/2], arccos [0, π], arctan (−π/2, π/2), two-argument arctan(y, x) (−π, π], arccot (0, π), arcsec [0, π] without π/2, and arccsc [−π/2, π/2] without 0, with the matching degree ranges. In degree mode a result within 8 ulp of a multiple of 15 returns that multiple exactly: arcsin 0.5 is 30, arctan 1 is 45 and arccos(−1) is 180. In radian mode arcsin 1 is π/2 (confirm the arccot range by REA behaviour capture in Phase 1). (Phase 1; verified by unit test)
  - _Amended 2026-10-19 (appendix F decision 2, Desmos behaviour wins):_ an inverse trig result in degree mode is the radian result divided by π/180, with no rounding: arcsin 0.5 is 30.000000000000004 and arccos 0.5 is 60.00000000000001, while arctan 1 is 45 and arccos(−1) is 180; two-argument arctan returns [−π, π], with arctan(−0, −1) = −π; arccot(x) is arctan(1/x) for x > 0 and π/2 − arctan(x) otherwise (function catalogue, captured live).
- **NM-29** Switching the angle unit or complex mode starts a new evaluation generation (AR-46) in the same task as the switch. No message from the superseded generation updates any row or curve after the switch. Every row value and every curve reflects the new setting within 250 ms of the switch for a 20-row list drawn from the Phase 1 corpus on the desktop CI profile. (Phase 1; verified by browser test)

### 4.5 Lists and table columns

- **NM-30** Lists are indexed from 1. A non-integer index is rounded down first (Desmos, captured 2026-10-19: `L[1.6]` = `L[1]`, `L[0.6]` undefined); an index out of range gives undefined, and a list of indices, or several items (`L[1,3]`), gives a list (`L[[1,3]]`). A `[` after any term indexes it, as in Desmos's parser (`(L+1)[2]`, `L^{2}[1]`). Indexing a number or a point, or indexing by a point, is the row error "Cannot index {a number} with {a number}.", each side named "a number", "a point", "a list of numbers" or "a list of points" (Desmos's ListAccess signature: `5[1]`, `a[1]` with a=5, `(1,2)[1]` "Cannot index a point with a number.", `L[(1,2)]` "Cannot index a list of numbers with a point."); any other non-list target analysis cannot type is undefined. `L[x]`, and an index of any list that uses no variable (`L[2...][x]`, `L[L>3][x]`), graphs as a step function. (Phase 2; verified by unit test)
- **NM-31** `L[i...j]` slices inclusively: it indexes by the range's elements, so it runs backwards when j < i and is not cut at the list's end (`L[8...20]` is L[8] then undefined). An empty start side is 1 and an empty end side the list's length (`L[2...]`, `L[...3]`, `L[...]`). `L[c]` keeps the elements for which condition c is true, paired by position up to the shorter list (`L[L>2]`, `L[[1,2,3]>2]` keeps L[3]); a condition that holds or fails everywhere keeps all or none. A range or filter that uses x, y or a name no row defines is "Can't plot a list whose length depends on free variable 'x'." (`L[i>2]` names 'i'; Desmos raises it for any list whose length depends on a free variable). (Phase 2; verified by unit test)
- **NM-32** Operators, one-argument built-ins and user functions apply element by element, and a scalar combines with every element. A user function receives a list argument whole, so its body broadcasts (`f(a)=a^{2}+1` gives `f([1,2,3])` = [2, 5, 10]). Functions that take a whole list, such as mean, total and sort, do not broadcast over that list; FN- marks each one. A list holds numbers or points (`[(1,2),(3,4)]`, and a point whose parts are lists, G-3); a list that mixes numbers and points is the error "All elements of a list must have the same type.", Desmos's text. Points add, subtract and negate coordinate by coordinate, scale by and divide by a number, and multiply each other with `\cdot` to their dot product, a number; `|P|` is P's length. Desmos's errors apply to the rest: "Cannot add a point and a number.", "Cannot divide a number by a point.", "Cannot raise a point to a number.", "Cannot multiply a point by a point." for two points written side by side, and "Cannot use a point as a coordinate of a point." (_amended 2026-10-20, M4, captured 2026-10-19_). (Phase 2; verified by unit test)
- **NM-33** Lists of different lengths are truncated to the shorter one, so `[1,2,3]+[10,20]` is `[11,22]` and `(L_{1},L_{2})` pairs only up to the shorter length. (Phase 2; verified by unit test)
- **NM-34** A nested list is an error with the message "Cannot store a list of numbers in a list." (the reference's text, R-2), so `[x_{1},x_{1}]\sim[y_{1},y_{1}]` with list columns x₁ and y₁ is that error. Analysis finds it from the rows (a list literal, range or list-valued name, call or expression inside list brackets or as a range bound); evaluation reports any it could not see, such as a function that returns a list. (Phase 2; verified by unit test)
- **NM-35** A list, including a range or comprehension result, holds at most 10,000 elements; a longer one is the error "Lists may not have more than 10,000 elements." (Desmos's wording, adopted 2026-10-19 under appendix F decision 2). (Phase 2; verified by unit test)
- **NM-36** A range is the values written before its ellipsis (the starts) and after it (the ends). One start steps by 1, or by −1 when the last end is below it; more step by s = second start − first start. As in Desmos, the element count is n = round((last end − first start)/s) + 1, rounding halves up, so the last element can pass the bound by up to half a step, and the elements are first start + k·s; the bound itself is never substituted. Every other written value must sit on that sequence (within 10 bits): the k-th start at element k and each end but the last at its place counted back from the last element, so `[1,2,3,...,10]` and `[1,...,9,10]` are `[1, 2, …, 10]` and `[1,2,4,...,10]` is an error. That, a count that is not finite (a bound that is not a real number, or s = 0), or a count below the number of starts or of ends is Desmos's error "Ranges must be arithmetic sequences."; a list bound is NM-34's error. Desmos computes the count and elements in exact fractions where they fit (numerator and denominator up to 2^53 − 1), and so does the calculator, reading each double as the simplest fraction that rounds to it: `[0,0.1,...,1]` is exactly 0, 0.1, 0.2, 0.3, …, 1 (never 0.30000000000000004) and `[1,1.1,...,1.25]` counts 2.5 steps, rounded to 3, so it is `[1, 1.1, 1.2, 1.3]`. So `[10...1]` has 10 elements, `[1...3.5]` is `[1, 2, 3, 4]`, `[0.5...3]` is `[0.5, 1.5, 2.5, 3.5]`, `[1,3,...,10]` is `[1, 3, 5, 7, 9, 11]`, `[10,8,...,1]` ends at 0, `[1...3.0000000001]` is `[1, 2, 3]`, and `[1,3,...,1]`, `[1,2,...,0]`, `[1,1,...,5]` and `[1...0/0]` are errors (captured from Desmos 2026-10-19, function catalogue; the fraction counts, the extra starts and ends and the unsnapped last element follow Desmos's range builder and are not yet captured live). (Phase 2; verified by unit test)
- **NM-37** A comprehension over several names forms every combination, with the first listed name varying fastest (confirm by REA behaviour capture in Phase 2). (Phase 2; verified by unit test)
- **NM-38** A list result shows its first 30 elements, then `…`. (Phase 2; verified by unit test)
- **NM-39** A table column is a list. Trailing blank cells are trimmed, and an interior blank cell is an undefined element. (Phase 3; verified by unit test)
- **NM-40** Point lists and the two-list data functions skip any pair in which either element is undefined; D-2 regressions and FN- cov, corr and spearman consume paired lists under this rule. A single-list statistic over a list that contains an undefined element returns undefined, except count (FN-5), so the mean of a column with an interior blank is undefined (confirm by REA behaviour capture in Phase 3). (Phase 3; verified by unit test)
- **NM-41** A condition compares full double values: `=` is true only for equal values, and any comparison with undefined is false (confirm `\{0.1+0.2=0.3:1,0\}` by REA behaviour capture in Phase 2). (Phase 2; verified by unit test)

## 5. Graphing (G-)

### 5.1 What graphs

- **G-1** `y=f(x)`, `x=g(y)`, implicit equations and inequalities graph. Shaded regions have a dashed boundary for strict inequalities and a solid one for non-strict. (Phase 1; verified by unit test)
- **G-2** Polar `r=f(\theta)`, parametric `(f(t),g(t))`, point lists built from lists, piecewise `\{\}` and domain restrictions graph. Single points are G-7. (Phase 2; verified by unit test)
- **G-3** Lists, ranges, comprehensions and lists of functions graph according to NM-30 to NM-38 and G-22. A point whose parts are lists, such as `(L_{1},L_{2})` or `(L,5)`, and a list of points such as `[(1,2),(3,4)]` are point rows that draw one dot per defined pair, paired by NM-33 (shipped by the 2026-10-18 lists package). (Phase 2; verified by unit test)
- **G-4** Points of interest, labels, trace and draggable points follow POI-1 to POI-16. (Phase 2; verified by browser test)
- **G-5** Pan works by drag and arrow keys. Pinch zooms, and the wheel zooms about the pointer by a factor of 17/16 per wheel event (`WHEEL_ZOOM_FACTOR`); a sideways wheel (deltaX with deltaY 0) zooms too, and zooming in with the pointer within 50 CSS px of the origin on both axes zooms about the origin itself (`WHEEL_ORIGIN_SNAP_PX`; measured on Desmos, 2026-10-21). A pointer press on the graph focuses it without showing the keyboard focus ring. Zoom In and Zoom Out zoom about the view centre by a factor of 2 per press. Home restores the default view: x from −10 to 10, y centred on 0, equal units on both axes (observed on 2026-10-16: y from −8.60887 to 8.60887 in the 1440×900 desktop layout). AN- sets the animation timing (confirm the zoom factor by REA behaviour capture in Phase 1). (Phase 1; verified by browser test)
- **G-6** Function definitions with one or more parameters (`f(x)=…`, `g(a,b)=…`) can be used from any row, in any order (RC-4, RC-9). (Phase 1; verified by unit test)
- **G-7** A point `(a,b)` with numeric coordinates draws as a dot within 0.5 px of its position. A point with an undefined coordinate is not drawn. (Phase 1; verified by unit test)
- **G-8** Lines from `x=c`, `y=c` and one-variable equations (RC-12) span the whole view, within 0.5 px of c. (Phase 1; verified by unit test)

### 5.2 Curve correctness

These rules are checked on the sampler's polylines and contours, not on pixels.

- **G-9** No segment crosses a pole. For `\tan x`, `\frac{1}{x}` and `\frac{x^{2}-1}{x-2}`, both endpoints of every segment lie in the same interval of continuity. (Phase 1; verified by unit test)
- **G-10** Curves reach their domain endpoints. `\sqrt{1-x^{2}}` ends within 0.5 px of (±1, 0); `\sqrt{x}` and `\sqrt{x-3}+2` start within 0.5 px of (0, 0) and (3, 2); and `\ln x` continues to the bottom edge of the view. (Phase 1; verified by unit test)
- **G-11** Every polyline vertex lies within 0.5 px of the curve, and every segment midpoint lies within 0.5 px of it, measured perpendicular in pixels. This holds in the default view and after a 10^6× zoom-in about (1, f(1)) for `x^{2}`, `x^{10}`, `e^{x}`, `\sin x`, `\frac{1}{x}` and `\tan x`, because the sampler refines where slope or curvature is large. (Phase 1; verified by unit test)
- **G-12** In every pixel column where f is defined throughout, the drawn vertical extent covers at least 90% of f's true range over that column, clipped to the view; the reference uses 64 samples per column. Steep regions therefore reach the view edge, and unresolvable oscillation, such as `\sin(100x)` in the default view or `\sin\frac{1}{x}` near 0, draws as a filled band, never as a false smooth curve. (Phase 1; verified by unit test)
- **G-13** Removable holes and isolated undefined points, such as x = 1 in `\frac{x^{2}-1}{x-1}`, leave no visible break wider than 1 px and get no marker. (Phase 1; verified by unit test)
- **G-14** Jumps in `\operatorname{floor}(x)`, `\operatorname{round}(x)`, `\operatorname{sign}(x)` and piecewise steps get no connector, and the polyline on each side ends within 0.5 px of the jump's x. (Phase 2; verified by unit test)
- **G-15** Each explicit, polar or parametric curve uses at most 20,000 evaluations per view, and each implicit curve or region at most 250,000. Work beyond the budget falls back to the G-12 band, never to an invented curve. (Phase 1; verified by perf test)

### 5.3 Implicit curves and inequalities

- **G-16** Implicit curve points lie within 0.5 px of the true zero set. Closed curves such as `x^{2}+y^{2}=25` have no gap wider than 1 px, and `xy=6` draws both branches with no connector. With `y=5`, both the circle and the tangent line draw, and (0, 5) lies on both within 0.5 px. (Phase 1; verified by unit test)
- **G-17** An inequality shades the side where it holds: every pixel centre more than 1 px from the boundary is shaded exactly when the inequality is true there, and the boundary lies within 1 px of the curve. Compound inequalities such as `1<y<3` shade between both boundaries. Where two shaded rows overlap, the overlap has a higher contrast ratio against the paper than either region alone (TH-8), and shading never lowers a curve below its contrast target (D9, TH-). (Phase 1; verified by unit test)
  - _Amended 2026-10-19 (F-A1):_ the clauses on overlap contrast and on curve contrast targets are dropped: every fill is 40% and overlaps stack with no cap, as in Desmos; see `f-desmos-parity.md`, amendment F-A1.
- **G-18** A restricted inequality such as `y>x\{x>0\}` shades only where the restriction holds, and a polar inequality such as `r<2` shades the enclosed region. (Phase 2; verified by unit test)

### 5.4 Polar and parametric curves

- **G-19** Polar curves measure θ in the current angle unit (NM-25). The default domain is 0 ≤ θ ≤ 12π (0 ≤ θ ≤ 2160 in degrees). Negative r plots in the opposite direction, `r=c` is a circle, and `\theta=c` is the full line through the origin (confirm the default domain and `\theta=c` by REA behaviour capture in Phase 2). (Phase 2; verified by unit test)
- **G-20** Parametric curves default to 0 ≤ t ≤ 1. Polar and parametric rows show their domain as editable inline bounds (`0\le\theta\le12\pi`, `0\le t\le1`), and a restriction on the row narrows that domain. (Phase 2; verified by component test)
- **G-21** Polar and parametric curves meet G-9, G-11 and G-12 over their parameter range, and domain bounds or restrictions clip within 0.5 px of the bound's point. (Phase 2; verified by unit test)
- **G-22** `y=[1,2,3]x` and other list-valued curves draw one curve per element, all in the row's colour and style. Until this ships (deferred by the 2026-10-18 lists package), a row that would graph a list-valued curve, line set or region, including a one-parameter function whose body is a list, is the `unsupported` row error "Graphing a list of curves isn't supported yet.", never a curve of undefined values. (Phase 2; verified by unit test)
  - _Amended 2026-10-20 (shipped on claude/calculator-listcurves):_ a list-valued curve, line set, region or one-parameter function graphs one branch per element, up to 10,000 branches as in Desmos; lists of different lengths give the shortest length, and the "Graphing a list of curves isn't supported yet." error is gone. `repeat(1,x)` keeps its list-length error, and `[1,2]<3` neither graphs nor errors, as in Desmos. Each branch has its own points of interest and trace; two branches of one row cross without a dot. Open gap: where list regions overlap, Desmos shades darker, and ours shades the row's union once.

### 5.5 Viewport limits and parity

- **G-23** Zooming in stops at a span of 10^-9·max(1, |centre|) per axis, and zooming out stops at a span of 10^15. No bound goes beyond ±10^15, and G-11 holds at both limits. (Phase 1; verified by unit test)
- **G-24** Every golden-corpus case under `src/lib/calculator/core/corpus/` (PR-39) that graphs renders and meets G-9 to G-17. (Phase 3; verified by unit test)
- **G-25** Mark sizes (appendix F, the Desmos feel): curves stroke 2.5 CSS px (4 px for the selected row, POI-17), points are 10 px discs (open circles and crosses stroke 2 px, D-12), strict inequality boundaries dash 12 px on and 6 px off, axes are 1.5 px and gridlines 1 px, each snapped to device pixels. (Phase 3, built in the parity work; verified by unit test)

### 5.6 Documented limits (not gates)

The calculator README documents these limits. None of them blocks a phase.

- Double-root contours such as `(y-x)^{2}=0`, and isolated solution points such as `x^{2}+y^{2}=0`, may not draw.
- The self-intersection point of an implicit curve, such as a figure-eight, may show a gap of up to 2 px.
- Implicit components less than 1 px across may not draw.
- Integer arithmetic beyond 2^53 loses precision.

| Graph kind                                     | Intercepts                       | Extrema                                                                               | Intersections |

- **POI-1** Points of interest appear only for the selected row's graphed curves (POI-17), as small grey dots without labels; with no row selected none are drawn. Hidden rows and rows with errors have none. (Parity; verified by browser test)
- **POI-2** Each graph kind gets the kinds of point of interest that the coverage table gives it; a circle or other implicit curve gets its axis intercepts and its top and bottom points (appendix F). (Parity; verified by unit test)
- **POI-3** Regression curves (D-2) get the `y=f(x)` points of interest. (Phase 3; verified by unit test)
- **POI-4** Intersections are found between the focused row's curves and every other visible graphed curve, including inequality boundaries and vertical lines. (Phase 2; verified by unit test)
- **POI-5** Detection is scale-invariant. Roots come from sign-change bracketing with a bracketing solver, and touching roots from local minimisation of |f| relative to f's local scale. No absolute threshold on |f| is used, so `y=10^{-8}(x-3)` has exactly one root, at 3. (Phase 2; verified by unit test)
- **POI-6** Excluded: poles (`\tan x` has no intercepts at its poles), removable holes (`\frac{x^{2}-1}{x-1}` has nothing at x = 1), restriction endpoints that are not true zeros, and anything outside the row's domain or restriction. (Phase 2; verified by unit test)
- **POI-7** An even-multiplicity root such as (x−2)² is reported once. Points of interest closer than 10^-9·max(1, |x|) (10^-7·max(1, |x|) when one is an extremum, POI-11's extremum accuracy) merge into one dot with one label that lists every kind; for (x−2)² that is the zero and the minimum at (2, 0), spoken with the combined kind words of A11Y-9. (Parity; verified by unit test)
- **POI-8** Corner extrema, such as the minimum of |x−1| at (1, 0), are found from a sign change in slope. (Phase 2; verified by unit test)
- **POI-9** The search covers the view widened by 10% on each side. Dots are drawn only inside the view and are recomputed when panning or zooming settles; panning and zooming keep the selection (POI-17) and close every open label (POI-13). (Parity; verified by browser test)
- **POI-10** When a curve has more than 100 points of one kind in the search region, that kind is hidden until the view is zoomed in, so no partial set is shown (confirm by REA behaviour capture in Phase 2). (Phase 2; verified by unit test)
- **POI-11** Simple roots and intersections are accurate to 10^-10·max(1, |x*|) in x. Extrema are accurate to 10^-7·max(1, |x*|) in x and 10^-12·max(1, |y*|) in y. A root of multiplicity m is accurate to 10·ε^(1/m)·max(1, |x*|), where ε = 2.2×10^-16. (Phase 2; verified by unit test)
- **POI-12** A point-of-interest label rounds each coordinate to d decimals, where d = clamp(max(5, ceil(−log10 u) + 3), 0, 12) and u is that axis's world units per px (appendix F decision 2: Desmos prints 5 decimals at the default view, 6 at 8x zoom in and still 5 at 8x zoom out). Trailing zeros are trimmed, so integer and terminating values print exactly (`2`, `−0.5`, `0.8`); negative values use a true minus sign and values below 1 a leading zero; a label never shows more digits than POI-11's accuracy supports, and outside NM-2's range it uses the ×10^n form. So in the default 800 px wide view, the root of x²−2 labels as 1.41421. (Parity; verified by unit test)
- **POI-13** Clicking or tapping a grey dot of the selected curve turns it into a larger dark dot and opens its `(x, y)` label, formatted by POI-12; several labels can be open at once and opening one never closes another; clicking an open dot again closes only its label; a click on a point of interest of an unselected curve only selects that curve (a second click opens the label); clicking empty graph paper closes every label and deselects the row; focusing or editing a row, the zoom buttons, the graph keys and panning close every label; labels never persist across deselection; Escape leaves open labels alone, as Desmos does: the next press closes them (amended 2026-10-21, owner decision); A11Y- covers keyboard and screen-reader access (appendix F requirements 4 to 10). (Parity; verified by browser test)
- **POI-14** Pressing on a curve and dragging along it traces the curve: a dot in the curve's colour with a live `(x, y)` label (no export action) stays on the curve at the point nearest the pointer, even when the pointer leaves the curve; x is rounded to clamp(ceil(−log10 u) + 1, 0, 12) decimals (the view's pixel precision) and y is the curve's value at that rounded x shown to at most 5 decimals; on a fine pointer the trace snaps to a point of interest within 3 px and then shows that point's POI-12 label; releasing removes the dot and label and pins nothing (appendix F requirements 16 to 20). (Parity; verified by browser test)
- **POI-15** A point can be dragged when each coordinate is a numeric literal or a bare slider name, or when one coordinate is a bare slider name and the other depends only on that slider. Dragging rewrites the literals or sets the sliders to values rounded by POI-12, so `(a,a^{2})` moves a and follows the parabola; other points stay fixed. (Phase 2; verified by browser test)
- **POI-16** The golden cases in the table below pass, using the default view unless stated. (Phase 2; verified by unit test)
