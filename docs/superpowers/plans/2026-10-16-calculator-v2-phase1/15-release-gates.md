## Rules

- R1. Every command runs from the worktree root under Node 22 (`n exec 22 <command>` on the lead's machine); builds export the gate environment of `00-index.md` section 1; `npm run test:e2e`, the AR-65 spec and `test:visual:regression` need `.env.local` copied from the main checkout without `CALCULATOR_V2_ROLLOUT`.
- R2. Unit: `npx vitest run <file> -t "<pattern>"`. Browser: `npm run test:calculator -- <spec> -g "<regex>"` (all five projects unless a step names some). Turbopack: `npx playwright test --config=playwright.calculator-v2-e2e.config.ts` with no other `next dev` running in the worktree.
- R3. Wave 8 fix rule (00-index section 4): when a check here fails inside a file another package owns, stop, fix it in a separate commit whose message is `Fix <ID>: <what> (<NN-key>)`, rerun, then continue. Never loosen an assertion of this package to pass.
- R4. Port and gate steps (Tasks 3, 4, 7 to 9, 12 and 13, and the perf spec of Task 11) check behaviour that 02 to 14 shipped, so their run step says "Expected: PASS on first run"; a failure becomes an R3 fix task. Task 3's coverage test is such a gate: it reads the corpus the earlier packages built, including the nine counted cases, for eleven IDs, that 02 and 04 write at this package's request (04's six are in `04-semantics-2-eval.md` Task 9; 02's three are in `02-parser.md` Tasks 7, 10 and 11). New code (Tasks 2, 5 and 6, Task 10's baselines and Task 11's baseline check) is test-first and must fail first. A test that passes on its first run has never been seen failing, so each one (every test of Tasks 3, 4, 7, 8, 9 and 12, the five tests of Task 11's `perf.spec.ts`, and Task 6's eager-import test, which guards code 12 and 14 shipped) has a mutation check in its task's "Mutation checks" step, in 14's form: after the task's commit, a temporary edit to the shipped module the test checks, the exact command, the assertion that must fail, then `git checkout -- <file>` and a passing rerun. Task 13 adds no test, so it has no mutation. Every mutation starts from a clean `git status --short`, is reverted by its `git checkout -- <file>` before the next command, and is never committed (it is not an R3 fix, so 00-index section 4's wave-8 rule is untouched). Its command runs the one test: `-t` or `-g` with the test's ID followed by a space (so `"V1-1 "` never matches V1-10), or with the title's first words where several tests share an ID; `test:calculator` mutations run on `--project=calculator-chrome` only, and Task 12's use its Step 2 command unchanged apart from `-g`. A mutation whose test still passes means the test is vacuous: strengthen that test in this package's file in a new commit (never loosen it), rerun both the mutation and the plain command, and list the test in the Task 13 hand-off.
- R5. Chromium-only measurements (`perf.spec.ts`, the CPU throttle, long-animation-frame attribution) and the one visual baseline set run on `calculator-chrome` only, skipped elsewhere with a reason (by project name, not `browserName`, so calculator-android does not run them; 00-index section 4's "Chromium-only checks" says the same). Fixtures are synthetic; no step submits an answer (diagnostic Skip and Previous, practice "Fixture retake" and question changes only).
- R6. Browser test sources in the part files are untagged and dense (11-seam's style): put each statement on its own line when writing them; Prettier does the rest. Every file this package creates stays under 700 lines.
