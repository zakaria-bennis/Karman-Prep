## Serious

### S1. Admin tables (`/admin/users`, `/admin/cohorts`) are unusable on mobile

The role/tier/links/Impersonate columns scroll off-screen at any viewport
under ~600px. **Confirmed across four engines** — Chromium desktop
emulation, Firefox, Pixel 7 (Chrome on Android), and WebKit (Safari).
The cross-engine test cascade caught it: `student_mid mobile · /dashboard/student`
failed in **`visual-firefox`** AND **`mobile-chrome`** because the helper
clicks an Impersonate button it can't reach without horizontal scroll.

Admins on a real iPhone literally cannot click Impersonate, change a
user's role, or see linked-students for parents without a horizontal
scroll most users won't think to perform.

**Evidence:**

- `tests/visual/snapshots/visual-firefox/admin/mobile/admin_users.png`
- `tests/visual/snapshots/visual-webkit/admin/mobile/admin_users.png`
- `tests/visual/snapshots/visual/admin/mobile/admin_users.png`
- Failed tests in `mobile-chrome` (Pixel 7) and `visual-firefox`.

**Fix:** make the admin tables responsive — either collapse to cards
at < 768px, or move the action column to a dedicated row-detail menu
(kebab icon). Same fix applies to `/admin/cohorts`.

### S2. Critical a11y: `<select>` element without an accessible name on admin pages

Both `/admin/users` and `/admin/cohorts` ship a cohort-filter dropdown
with no `aria-label` or visible `<label>` association. axe-core flags
this as **critical** (WCAG 4.1.2). Screen-reader users hear the options
but not the field's purpose.

**Evidence:** `tests/visual/snapshots/a11y/admin__admin_users.json`,
`admin__admin_cohorts.json` — `id: "select-name"`, `impact: "critical"`.

**Fix:** add `aria-label="Filter by cohort"` (or wrap in a `<label>`)
to the cohort dropdown in `src/app/admin/users/UsersClient.tsx` and the
matching one in cohorts.

### S3. Three pages have color-contrast violations (WCAG AA)

axe-core flags `serious` color-contrast on `/admin/users`,
`/admin/cohorts`, and `/dashboard/student`. Two of the three pages also
have the critical select-name violation.

**Evidence:** all three a11y JSON reports under
`tests/visual/snapshots/a11y/`.

**Fix:** open the helpUrl in each report (links to dequeuniversity for
the specific rule) to see which element fails. Most likely candidates:
muted-grey body text on dark surfaces (`text-slate-500` on `bg-slate-900`
is below 4.5:1).

### S4. `docs/feature-inventory.md` is now stale

The audit-source-of-truth doc still says about admin impersonation:

> "Generic impersonation only. Can't impersonate a specific student to
> reproduce their bug."

PR #51 (granular impersonation) shipped this. Other inventory items
might be similarly stale.

**Fix:** rewrite the impersonation section, and skim the rest of the
doc for any "currently broken" claim that PRs #44-#59 have actually
resolved.

### S5. `develop` is 59 PRs behind `main`

`CLAUDE.md` says "Main branch (you will usually use this for PRs):
develop". Reality: every PR today (#52-#59) plus prior session work
(#44-#51) merged into `main`, leaving `develop` stuck at commit #1.

**Fix:** pick a direction. Either fast-forward `develop` to `main`
(if it's still meant to be the integration branch) or update
`CLAUDE.md` to call out that `main` is the working trunk.

### S6. 7 npm vulnerabilities (1 moderate, 6 high)

`npm audit` flags advisories. The flagged one in plain view is
`postcss < 8.5.10` (XSS via unescaped `</style>` in stringify output)
nested under Next's deps.

**Fix:** `npm audit fix` is the headline answer; verify the dependency
tree updates Next or its postcss subdep without breaking the build.
If `audit fix` requires `--force` to resolve, evaluate the breaking
changes case-by-case.

### M2. Visual harness has a Firefox-mode helper bug

`impersonateByEmail()` in `tests/visual/snapshots.spec.ts` clicks the
Impersonate button without scrolling first. Chromium auto-scrolls
clickable targets into view; Firefox doesn't. At mobile viewport the
button is off-screen (see S1) and the click silently misses, causing
test #47 to fail and the next 17 tests in the same serial block to be
skipped.

**Fix:** add `await row.getByRole("button", { name: /Impersonate/i })
.scrollIntoViewIfNeeded()` before `.click()`. **Note:** test fix is
straightforward, but the underlying product issue (S1) is the real
problem — the user has the same experience.

### M3. Cron triggers configured but not in DB-deploy CI guardrails

`wrangler.toml` has 4 cron schedules (`0 6 * * *`, `*/5 * * * *`,
`*/2 * * * *`, `0 14 * * *`). The 5-min and 2-min crons could
hammer Supabase or Stripe if a regression introduced a tight retry
loop. No alerting wired up for runaway crons.

**Fix:** add a Sentry alert when cron throughput exceeds N invocations
in 24h, or instrument each `/api/cron/*` route with rate-limit logs.

### M4. Next.js scroll-behavior warning

Console emits: `Detected scroll-behavior: smooth on the <html>
element. To disable smooth scrolling during route transitions, add
data-scroll-behavior="smooth" to your <html> element.`

**Fix:** in `src/app/layout.tsx`, change
`<html lang="en" className="dark" suppressHydrationWarning>` to
`<html lang="en" className="dark" data-scroll-behavior="smooth"
suppressHydrationWarning>`.

### M5. 56+ stale remote feature branches

Most are 1 commit ahead of `main` — i.e., they were squash-merged but
the branch wasn't deleted, leaving dangling remote refs. Examples:
`origin/zakaria/dev-auth-bypass`, `origin/zakaria/seed-dev-fixtures`,
etc.

**Fix:** `git push origin --delete <branch>` for each, or batch via
`git remote prune origin` after deleting upstream. Doesn't affect
function but clutters branch listings.

### M6. `dev_seed_tutor` fixture is too empty

The seeded tutor has no cohort assignment + no 1:1 student, so the
`/tutor` portal renders a double-empty-state ("No cohorts yet · No
students assigned"). Realistic for a brand-new tutor but blocks visual
regression of the populated tutor portal.

**Fix:** in `scripts/seed-dev.mjs`, give `dev_seed_tutor` one tutor
assignment to `dev_seed_student_mid` and / or one cohort membership.

## Nit / calibration

### N1. `docs/design-tokens.md` type scale doesn't match reality

Token drift checker flagged 15+ "violations" but most are the docs
being wrong. e.g. the `/admin/users` h1 ("Users") is `24px / 32px
line-height` — Tailwind's `text-2xl font-bold`. The docs claim
`32px / 36.8px` for h1.

**Fix:** update `docs/design-tokens.md` to match actual values (h1
= 24px, line-height = 32px, etc.). Run `tokens.spec.ts` post-update;
if any real drift remains, that's the genuine signal.

### N2. Token checker flags `linear-gradient(...)` as "raw hex"

The Karman logo uses an inline `linear-gradient(90deg, #..., #...)`
for the animated wordmark gradient. The token-drift checker's
hex-detection regex matches inside the gradient string and reports
it as a violation. It's not — Tailwind doesn't tokenize gradient
color stops.

**Fix:** in `tests/visual/tokens.spec.ts`, exclude inline styles
that begin with or include `linear-gradient` / `radial-gradient` /
`conic-gradient` before applying the hex regex.

### N3. Timing helper reports `-1` for the Impersonate hover

The button has no CSS `transition-property` for the background-color
change (Tailwind `hover:bg-amber-500/10` ships unanimated by default).
The helper correctly logged `no transition fired (button has no
transition-* CSS, or selector missed)` — but the JSON's `slow: false`
field is misleading.

**Fix:** in `tests/visual/timing.spec.ts`, change the `slow` field
to `"slow": deltaMs > SLOW_THRESHOLD_MS, "no_transition": deltaMs ===
-1`. Two booleans is more honest than one.
